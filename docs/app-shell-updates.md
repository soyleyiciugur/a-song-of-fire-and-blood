# Home Screen releases

`data/app-shell-release.json` is the central release authority. Version 1 is a baseline: it does not ask existing members to reinstall. Feature, content, and CSS releases leave this file alone. Keep an active reinstall release enabled across subsequent ordinary deploys so older installations can catch up.

`npm run build` runs `shell:check` first. The audit fingerprints manifest metadata, install-related layout metadata, and icon bytes. A changed shell blocks the build until `npm run shell:release -- "A concise reason for members"` records the next version. Review all indirect/dynamic metadata dependencies manually; include newly introduced sources in the fingerprint audit. This intentionally treats install metadata changes conservatively, since iOS caching behavior differs by OS version.

GitHub Actions runs the same audit on pushes and pull requests. Pushes needing review or declaring a new reinstall release create a deduplicated GitHub issue and mention the pushing account. GitHub delivery depends on that account's notification settings and repository Actions permissions. No email address or external messaging service is required.

Apply `20260914000000_app_shell_installations.sql` before deployment. Set the same `CRON_SECRET` in Vercel and GitHub Actions to enable the authenticated daily `/api/app-shell/publish` job and the successful-production-deployment hook. Each sends up to 50 pending accounts per run through the existing notification dispatcher, respecting Realm notices and deduplicating per release/account. Opening an outdated installation also delivers its notification immediately. No notification is sent during a build or preview check. Repositories without Vercel GitHub deployment-status events still have the daily Vercel job and on-open delivery.

Installations have separate UUIDs and account-backed acknowledgment rows. Acknowledging one device does not acknowledge another. Browser storage holds only the device pointer and guest fallback; account data, notification preferences, unread state and mascot history remain in their existing Supabase tables. iOS does not expose a reliable installed-manifest version or reinstall event. An unknown installation during an active release therefore needs explicit confirmation; it is never silently treated as proof of reinstall. The guide offers “I've added it again” only in standalone mode. Deleting browser storage loses its device pointer; a new pointer must be acknowledged. Sign-in restores account information, not a claimed OS installation identity.

The guide is `/app-update`. Before deleting the app, open that address in Safari or copy it there. A normal web link cannot guarantee Safari is launched. To make an optional Shortcut, create one named **ASOFAB Updater** in Apple Shortcuts: Show Alert with the four guide steps, then Open URLs with `https://a-song-of-fire-and-blood.vercel.app/app-update`. Select the installed-Shortcut checkbox to run it. Websites cannot detect whether that Shortcut exists; the manual guide always remains available. A Shortcut cannot remove or reinstall the Home Screen app.

After reopening, granted push permission allows a subscription repair attempt. A missing permission uses the existing explicit Enable action in Raven Settings; denied permission is never bypassed. “Disable here” is respected within the surviving installation. iOS may discard its session/storage when removing the app; the recovery links use existing sign-in and settings flows.

Apple references: [Shortcuts URL scheme](https://support.apple.com/en-nz/guide/shortcuts/apd624386f42/ios), [WebKit Home Screen push permissions](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/).
